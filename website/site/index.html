PUT IT TO WORK

Before your next build.

Check your scripts, validate a saved scene, and inspect errors from a short playtest. Keep the commands with your project so you can repeat the checks after a change.

Try this from the quickstart project, with its editor open and the addon enabled. Use your own saved scene path when you adapt it.

Turn it into a CI check

Read the validation results and returned error list before exporting. This sequence inspects a playtest; a CI gate also needs assertions and failure handling.

CLI first.
MCP when you want it.

MCP is a connection option. The automation toolkit works without it.

Use the CLI

Run commands from your terminal, reuse them in scripts, or add them to CI. Read the results directly, or pipe JSON into your next step.

Connect through MCP

KEEP CONTROL OF YOUR WORK

Your project stays yours.

Work with ordinary Godot scenes, scripts, and resources. Open them in the editor, review the changes in Git, and keep building with the tools you choose.

Inspect what changes

Your scenes, scripts, and resources remain project files you can read, edit, and version.

Undo supported scene edits

Supported scene operations use Godot's editor undo history. Script execution and file changes need their own review and recovery.

Keep a checkpoint

Save your work and commit a known working state before broad changes. Review the diff and test the result before keeping it.

Godot already has a CLI.
Swallowtail works with it.

Godot's built-in command line launches the engine and handles tasks such as imports, scripts, and exports. Swallowtail uses your Godot installation for those jobs and adds an interface to the editor session you already have open.

Start with the engine

Import assets, check scripts, run tests, and export builds through commands that invoke Godot and report the result.

swallowtail check .

Work in the live editor

Inspect the scene tree, change node properties, and validate saved scenes. Read state back as you work.

swallowtail scene tree

See what the game does

Play a scene, inspect runtime properties, send input, and check errors. Verify behavior in the running game.

swallowtail runtime tree

Swallowtail uses an installed Godot engine; it does not bundle one. Godot's command-line reference · How Swallowtail works

WHY THIS PROJECT EXISTS

I just wanted
to build games.

For my son.
For myself.

After twenty years as a programmer, I wanted to spend more time making games. I don't have the budget to hire a team for every idea, and I don't want to spend ten years on a project at the expense of my health or my family.

What I wanted was a toolkit that lets me work the way I want on any given day, and that includes using AI as one of the tools. Some days that is a terminal and a script I can run again. Some days it is an agent driving the editor while I review what it changed. Swallowtail gives both the same commands, so the choice stays mine at every step between an idea and something you can actually play.

I understand the concerns about this technology. You don't have to agree with my choices, and I respect that. I'm here to make games and share a tool, not to fight. Questions and criticism are welcome. Bullying and personal attacks aren't.
