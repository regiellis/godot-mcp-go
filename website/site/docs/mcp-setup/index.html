Use with an AI client

Run swallowtail as an MCP server so Claude, Cursor, VS Code, or Codex can drive Godot.

swallowtail serve gives an MCP client the same complete workflow as the CLI: discover the live engine, build in the open editor, run and play the game, observe state, debug failures, fix them, and verify the result. It runs as a Model Context Protocol server over stdio. Clients that speak streamable HTTP can skip the binary and connect straight to the editor, which hosts its own MCP endpoint.

Two tool modes#

warning
The typed list costs about 52,000 tokens

The full typed surface measures ~332 tools and ~52,000 tokens of schemas, sized for big-context frontier models, which carry it comfortably with prompt caching. The single-tool mode measures ~470 tokens. Measurements, per-group breakdown, and the reasoning behind the default: What the tool surface costs.

By default, serve exposes each documented command as a typed MCP tool, such as node_add, with required parameters and a description. Definitions come from the live addon, including project-local commands, and refresh as described below. The generic godot_run tool accepts the dotted method name and its parameters:

For clients that cap the number of tools, run serve --typed=false to expose only godot_run. One tool still reaches all 332 registered commands while keeping the model’s context lean: the model discovers the live 4.7 API with engine.search / engine.class_info, then acts, instead of carrying every tool schema into the session. Both modes are deliberate: typed for schema-guided calls, single-tool for context economy.

tip

To drive a standalone running game with no editor open, godot_run accepts game: true, and the typed runtime_* / input_* tools carry an optional game parameter that routes the call to the game’s own server. See the direct-to-player channel.

Write the config automatically#

swallowtail configure writes an MCP-server entry for a supported client, merging without clobbering your other servers:

Add --print to emit the snippet without writing (the safe path for uncertain global targets).

--project must name a real Godot project, meaning the directory holding project.godot or anywhere inside it. Configure refuses a directory that is in no project: the config it would write leaves the server unable to resolve a project root, so it falls back to port 9080 and skips the check that the answering editor is the right one.

Or configure by hand#

The Godot editor must be open with the plugin enabled, exactly as for the CLI. --project sets where the server discovers the addon port, so it survives an editor restart.

Editor restarts and catalog changes#

The stdio server refreshes tool definitions when the client lists tools, before a typed call, and after a successful generic editor call. Added or removed commands and changed schemas emit notifications/tools/list_changed. An identical catalog emits no notification. If the editor goes offline, the list falls back to godot_run; the same stdio process discovers the tools again when it reconnects. The same holds when the editor is down at connect time: serve starts with godot_run alone and adds the typed tools once the editor answers.

Progress and cancellation#

A stdio client requests progress by putting a string or integer progressToken in the tool call’s _meta, alongside name and arguments:

notifications/progress carries that token and an increasing progress value. Validation batches and imports count completed files; scenarios count completed steps. These updates include total when the count is known. Clients decide how to display them.

To cancel request 42, send:

Cancellation stops remaining scenario steps, script validations, or asset imports at a safe boundary. Timed scenario waits can stop early. Completed edits and inputs stay in place, and a playing game stays running until scene stop. A native compile/import or game command already underway may finish. Cancelled requests send no result or further progress; ping stays responsive during work.

Progress and cancellation currently apply to stdio. The HTTP endpoint below continues to return ordinary request results.

Or connect straight to the editor (streamable HTTP)#

The addon hosts a streamable-HTTP MCP endpoint inside the editor at POST /mcp on 127.0.0.1, so an MCP client that speaks streamable HTTP connects with no external process at all:

The endpoint picks the first free port in 9100-9115 and records it as http_port in <project>/.godot/swallowtail.json; pin a fixed one with the swallowtail/network/http_port project setting (Project → Project Settings → Swallowtail) or the SWALLOWTAIL_HTTP_PORT environment variable.

The tool surface mirrors serve: the generic godot_run plus every documented command as a typed tool, dispatched through the same command router with the same safety guards. Two settings tune it:

SettingDefaultEffect
swallowtail/network/mcp_httptrueturns the endpoint on or off
swallowtail/network/http_typedtruefalse lists only godot_run, the serve --typed=false role for tool-limited clients

The endpoint listens on loopback and checks the Origin header, so a web page you happen to have open cannot reach it: requests carrying no Origin (every native MCP client) or an origin whose host is localhost, ::1, or a loopback address are served, anything else gets 403, and the CORS header echoes the allowed origin rather than *. A browser-based MCP client running on http://localhost:<port> works unchanged. The WebSocket transport cannot be gated the same way. The threat model covers what that does and does not mean.

Reach an editor on another machine#

Both servers bind loopback and never listen on a network address. To drive an editor that runs on a different computer, forward the port over SSH. The request arrives on the editor’s own loopback with no Origin, so the gate passes, and your client config keeps the same http://127.0.0.1:9100/mcp URL.

Pin the port on the editor machine first, so it does not move between launches: set swallowtail/network/http_port to 9100 in that project. Then, on the machine running the client, open the tunnel and leave it running.

When the editor machine can reach the client machine but not the other way round, open the tunnel from the editor side with a remote forward instead: ssh -N -R 9100:127.0.0.1:9100 you@laptop. Either way, keep the forwarded end on loopback, which is the default; -g or a 0.0.0.0: bind address would expose the editor to that machine’s network.

A stdio client can skip the port entirely and run serve on the editor machine through SSH. This needs swallowtail on the remote PATH, key-based login that never prompts, and a remote shell that prints nothing on login, because stdout is the MCP transport and a stray banner corrupts it:

The CLI itself belongs on the machine with the project: ssh you@devbox and run swallowtail there. A tunnel extends the trust described in the threat model: anyone who can reach the forwarded port on the client machine can drive the editor.

note

stdio (swallowtail serve) remains the right choice for clients without streamable-HTTP support, and it adds the godot:// resources, the MCP prompts below, and the game: true routing to a standalone player. The HTTP endpoint’s strength is zero-install reach: if the editor is running, the server is running.

Read-only resources#

Beyond the tools, the server advertises read-only MCP resources under the godot:// scheme, so a client can pull context without spending a tool turn:

ResourceContents
godot://project/infoproject metadata
godot://project/treethe project file tree
godot://scene/treethe open scene’s node tree
godot://engine/singletonsregistered singletons
godot://editor/errorsrecent editor errors

Prompts#

serve also ships the durable playbooks as first-class MCP prompts, so a client can pull them with prompts/get, even when the editor is down:

PromptWhat it teaches
discover-then-driveground on the live engine API (engine.search / engine.class_info) before acting, and the durable editor rules
spatial-placementanchor, read real bounds back, seat with a raycast, verify numerically (optional target argument)
launch-recoveryrecover an unreachable editor from its discovery verdict instead of relaunching blindly
bug-hunttreat surprising results as tool bugs: root-cause, verify by reading state back
tip

The initialize reply also carries an instructions string with the same discover-then-drive and spatial-placement steer in compressed form, so the guidance rides along at every connect even without the skill installed.
